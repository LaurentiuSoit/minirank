# AGENTS.md for project MiniRank

Instructions for AI agents working in this repository. Read this before writing code.

## What this is

MiniRank is a keyword position tracker for a single configured website. A user adds
keywords (search phrases), and the app records a simulated daily ranking position
(1–100) for each one. All ranking data is generated locally through a seeding mechanism. No other data sources.
The app is single user. No account, session or authentication mechanism.

## Stack and constraints

- PHP 8, no framework. Plain PHP with PDO. This is a deliberate choice.
- SQLite, via PDO. No database server.
- No build step. Hand written CSS and vanilla JS. No npm, no bundler, no
  TypeScript, no CSS framework.
- No Composer dependencies unless I approve one first. Ask, explain what it buys us, and wait.

## Security rules. Non-negotiable

These are the rules I care most about. A diff that breaks one of them is wrong even
if the feature works.

1. Every SQL query uses a prepared statement with bound parameters. Never build SQL by string concatenation or interpolation, not even for values you believe are safe, not even for integers, not even in the seed script.

```php
   // Correct
   $stmt = $pdo->prepare('SELECT * FROM keywords WHERE id = ?');
   $stmt->execute([$id]);

   // Never do this
   $pdo->query("SELECT * FROM keywords WHERE id = $id");
   ```

2. Every value printed into HTML is escaped.

3. No secrets in the repository. No API keys, no credentials, no `.env` file committed. The SQLite database file is git-ignored and regenerated by the seed script.

4. Treat `$_GET` and `$_POST` as hostile. Validate and cast before use: keyword IDs are integers, the search term is a string with a length cap.

## Ranking rule

In regards to ranking, lower position numbers are better. Position 1 is the best possible ranking,
position 100 is the worst.

- position went from 37 to 12: the ranking improved.

- position went from 12 → 37: the ranking declined.

## Style

- `declare(strict_types=1);` at the top of every PHP file.
- Webpages should also work on mobile. Prioritize function over beauty. It doesn't have to be pixel perfect, it has to work. 
- Type hints on function parameters and return types.
- Functions over classes. Introduce a class only when there is real state to hold.
- Snake_case for database columns, camelCase for PHP variables and functions.
- Prefer obvious code over clever code. I have to explain every line of this project
  out loud to a reviewer. A compact one liner that takes two minutes to unpack is worse than four plain lines.

## Things not to do

- Do not add a framework. Not Laravel, not Symfony, not Slim. If you have any concerns you think might be resolved with a framework, ask me first, do not add anything on your own.
- Do not add abstraction layers. No repository interfaces, no service classes, no
  dependency injection container, no abstract base classes. This app has two tables.
  A function that runs a query is the right amount of structure.
- Do not refactor code I did not ask you to touch. If you spot a problem
  elsewhere, mention it in your reply and leave the code alone.
- Do not put SQL or business logic in `views/`. Views receive prepared data and
  print it.
- Do not write to the database from a GET request. Mutations go through POST.

## How to work with me

- Small diffs. One feature per change. If a request seems to need edits across
  more than three or four files, stop and propose a split first.
- Explain unfamiliar PHP syntax/clever code. I come from a Java and Typescript background and am not familiar with the specifics of PHP. Explain everything that might seem unclear/confusing to a beginner. I don't want to add code I don't understand.
- Flag your uncertainty. If you are unsure/guessing at an API signature or a SQLite
  behaviour, bring this up and let me make a decision.
- After each change, give me specific instructions on how to check it.

## Definition of done

A change is finished when:

- The app still starts with and the page loads.
- Linting passes on every file touched.
- Every new query is parameterized and every new output is escaped.
- The seeding mechanism still runs clean from an empty database.
